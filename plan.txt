Plan: EventQR – Offline-First Ticket Verification System
TL;DR: Build a three-tier system consisting of a Node.js/Express backend with PostgreSQL, a React Admin Panel for event management, and a Flutter Scanner App with SQLite for offline-first QR verification. QR codes will be signed with Ed25519 for tamper-proof validation. The scanner app syncs ticket data pre-event and queues check-ins for background sync. Multi-event support included.

QR Code Payload Structure

{
  "v": 1,                        // Version
  "tid": "ABC123",               // Ticket ID
  "eid": "evt_2026_dsc",         // Event ID
  "exp": 1760000000,             // Expiry timestamp
  "cat": "VIP",                  // Category
  "sig": "base64_ed25519_sig"    // Ed25519 signature
}

    Signing Flow:

Create payload without signature
JSON.stringify → UTF-8 bytes
Sign with event's Ed25519 private key
Append signature to payload
Base64 encode entire payload for QR
Verification Flow (offline):

Decode Base64 → JSON
Extract signature, rebuild unsigned payload
Verify signature with public key (stored locally)
Check expiry timestamp
Lookup ticket in local SQLite

Sync Strategy
Pre-Event:

Scanner registers with backend (gets API key)
Full ticket list downloaded to SQLite
Public key stored locally for verification
During Event (Offline):

QR scanned → verify signature locally
Check local SQLite for ticket existence
If valid & not checked-in → mark locally
Add to sync_queue table
Background Sync (When Online):

Periodic check for connectivity
Batch POST all sync_queue items
Backend applies conflict resolution (earliest wins)
Mark items as synced, remove from queue
Pull any new tickets (late additions)
Conflict Resolution:

Timestamp is recorded at scan time (device time)
Backend compares all check-ins for same ticket
Earliest timestamp wins, others flagged as duplicates
Fraud log created for duplicates

Key Decisions Made
Decision	Choice	Rationale
Backend	Node.js + Express	Fast development, JS ecosystem
Database	PostgreSQL	Robust, relational data fits well
Admin UI	React + Vite	Modern, fast HMR, rich ecosystem
Email	AWS SES	Scalable, cost-effective for small scale
QR Signing	Ed25519	Compact signatures, modern, public key can be safely embedded in app
ORM	Prisma	Type-safe, great DX
State (React)	Zustand or React Query	Lightweight, good for this scale
State (Flutter)	Riverpod	Modern, testable
Security Considerations
QR Tamper Protection: Ed25519 signatures prevent QR forgery
Scanner Auth: API keys per device, can be revoked
Admin Auth: JWT with refresh tokens, role-based access
Private Key Storage: Encrypted at rest in database
Rate Limiting: Prevent sync endpoint abuse
Audit Trail: All check-ins logged with timestamps
HTTPS Only: All API communication encrypted
